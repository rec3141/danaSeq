    MAG Analysis Pipeline¶

    Technology-agnostic downstream analysis for metagenome-assembled genomes (MAGs). Accepts a pre-computed assembly + depth table from any assembler and runs binning, annotation, taxonomy, metabolic profiling, mobile genetic element detection, eukaryotic analysis, ecosystem services mapping, phylogenetics, and interactive visualization.

    Quick Start¶

    cd mag_analysis
./install.sh && ./install.sh --check

# Basic run
./run-mag-analysis.sh \
    --assembly /path/to/assembly.fasta \
    --depths /path/to/depths.txt \
    --outdir /path/to/output \
    --annotator bakta --db_dir /path/to/databases

# All modules
./run-mag-analysis.sh \
    --assembly /path/to/assembly.fasta \
    --depths /path/to/depths.txt \
    --bam_dir /path/to/mapping/ \
    --outdir /path/to/output \
    --all --db_dir /path/to/databases

# Apptainer (HPC)
./run-mag-analysis.sh --apptainer \
    --assembly /path/to/assembly.fasta \
    --depths /path/to/depths.txt \
    --outdir /path/to/output \
    --all --db_dir /path/to/databases

    Pipeline Stages¶

    Binning¶

    Step Process Tool Description
    1a BIN_SEMIBIN2 SemiBin2 Self-supervised contig binning (needs BAMs)
    1b BIN_METABAT2 MetaBAT2 Depth + TNF binning (always runs)
    1c BIN_MAXBIN2 MaxBin2 EM-based abundance binning
    1d BIN_LORBIN LorBin Long-read-aware binning (needs BAMs)
    1e BIN_COMEBIN COMEBin Contrastive learning binning (needs BAMs)
    1f BIN_VAMB VAMB Variational autoencoder binning
    1g BIN_VAMB_TAX VAMB Taxonomy-guided variational autoencoder binning
    2a DASTOOL_CONSENSUS DAS Tool Score-based consensus of multiple binners
    2b BINETTE_CONSENSUS Binette CheckM2-guided bin refinement
    2c MAGSCOT_CONSENSUS MAGScoT Marker-gene-based consensus
    3 CHECKM2 CheckM2 Completeness and contamination assessment
    3b DEREP_GALAH galah + skani Species-level dereplication of the consensus bins, ranked by CheckM2

    Annotation¶

    Step Process Tool Description
    4a PROKKA_ANNOTATE Prokka ORF prediction + functional annotation
    4b BAKTA_BASIC Bakta CDS annotation (lightweight)
    4c BAKTA_EXTRA Bakta Full-database annotation (CDS, sORFs, expert systems; rRNA/tRNA/ncRNA and CRISPR are skipped)
    4d BAKTA_EXTRA_IDS Python Renames BAKTA_EXTRA features to the BAKTA_BASIC locus tag of the CDS at the same coordinates, since all protein tools run on the basic proteins; sORFs get new tags after the last basic one. Writes locus_tag_map.tsv

    Taxonomy¶

    Step Process Tool Description
    5a KAIJU_CONTIG_CLASSIFY Kaiju Protein-level contig classification
    5b KAIJU_CLASSIFY Kaiju Protein-level MAG classification
    5c KRAKEN2_CLASSIFY Kraken2 k-mer-based classification
    5d SENDSKETCH_CLASSIFY BBTools sendsketch MinHash taxonomy (GTDB)
    5e RNA_CLASSIFY barrnap + VSEARCH rRNA extraction + SILVA classification
    5f GTDBTK_CLASSIFY GTDB-Tk Genome-based taxonomy (160 GB RAM declared)

    Metabolism¶

    Step Process Tool Description
    6a KOFAMSCAN KofamScan KEGG ortholog assignment via HMM profiles
    6b EMAPPER eggNOG-mapper Ortholog annotation (COG, GO, KEGG, CAZy)
    6c DBCAN dbCAN CAZyme annotation via HMM + diamond + HMMER
    6d PROTEIN_DB_HMM, PROTEIN_DB_DIAMOND hmmsearch, DIAMOND Protein reference DBs under --protein_db_dir (CANT-HYD, HADEG, PGAP/TIGRFAM, ...), one task per DB
    6e MERGE_ANNOTATIONS Python Merge KofamScan + eggNOG + dbCAN + protein-DB hits per gene
    6f MAP_TO_BINS Python Assign annotations to MAGs
    6g KEGG_MODULES Python KEGG module completeness per MAG (55 bundled modules)
    6h MINPATH MinPath Pathway parsimony analysis
    6i KEGG_DECODER KEGG-Decoder Metabolic pathway heatmaps
    6j ANTISMASH antiSMASH Biosynthetic gene cluster detection
    6k ECOSSDB_MAP Python (ecossdb) Ecosystem services mapping (CICES 5.2)
    6l ECOSSDB_SCORE Python (ecossdb) Ecosystem service scoring
    6m ECOSSDB_SDG Python (ecossdb) UN Sustainable Development Goal mapping
    6n ECOSSDB_VIZ Python (ecossdb) Ecosystem services visualization
    6o METACYC_SEARCH DIAMOND Proteins against Rhea-annotated UniProtKB proteins (--metacyc_refs)
    6p METACYC_PATHWAYS Python MetaCyc reactions and pathway calls per DAS Tool MAG and community, with confidence (--metacyc_db)

    Protein reference databases¶

    --protein_db_dir DIR (with --run_metabolism; --db_dir resolves <db_dir>/protein_dbs) searches the annotation proteins against every database in DIR, one subdirectory per database. The layout is the one nanopore_live's --pollutant_dbs reads, so one directory serves both pipelines:

    File Meaning
    <name>/<name>.hmm HMM profiles, searched with hmmsearch
    <name>/<name>.dmnd DIAMOND database, searched with diamond blastp (best hit per protein)
    <name>/<name>.genes.tsv Optional catalogue: target gene category pathway subpathway description [threshold score_type motif]
    <name>/<name>.opts Optional cutoff: tc, ga, nc or an E-value for HMMs, optionally followed by resolve; id=,qcov=,scov=,evalue=,len=,bits= for DIAMOND

    Without an .opts file, HMMs use --hmm_cut (default tc), or the catalogue's per-target thresholds when <name>.genes.tsv has a threshold column; DIAMOND uses --protein_db_opts. Each database's hits are in metabolism/protein_dbs/<name>/<name>.protein_db.tsv, and merged_annotations.tsv gains a protein_db_hits column (<db>:<gene>, comma-separated). The results are stored per database, so adding one later searches only that one; after changing a database or its .opts, delete its metabolism/protein_dbs/<name>/ to search it again.

    An HMM search over more than --protein_db_chunk proteins (default 50,000) is split into chunks searched in parallel, 4 hmmsearch threads per chunk, since one hmmsearch gains little from more threads. E-values are computed against the whole protein set, so the hits are those of a single search. Give the step the node with --protein_db_cpus: on 72,231 proteins PGAP took ~2.2 CPU-hours and the full CATH FunFam library ~8.7, and both scale with total protein length.

    With resolve (e.g. 1e-3 resolve), the per-domain hits go through cath-resolve-hits, and only each protein's best non-overlapping set of models is kept. This is for libraries of overlapping families, such as CATH FunFam, where one protein otherwise matches dozens of related models.

    ./download-databases.sh --funfam writes <db_dir>/protein_dbs/CATH-FunFam/: CATH FunFam v4.3.0 (212,872 models), searched at 1e-3 resolve; --funfam-superfamilies 3.40.50.300,1.10.8 keeps only some superfamilies.

    ./download-databases.sh --pgap writes <db_dir>/protein_dbs/PGAP/: NCBI's PGAP HMMs, which hold the maintained TIGRFAMs (accessions TIGR*) plus NCBIfam and PRK models, searched at their noise cutoffs (nc; the trusted cutoffs NCBI uses for genomes are often too strict for metagenomes).

    MetaCyc pathways¶

    With --metacyc_db (and --metacyc_refs), mag_analysis predicts which MetaCyc pathways each DAS Tool MAG, and the community as a whole, carries. It does not run Pathway Tools on your data. Proteins get MetaCyc reactions through Rhea: DIAMOND hits to Rhea-annotated UniProtKB proteins, plus Bakta/eggNOG EC numbers and KofamScan/eggNOG KOs. Pathways are then called with PathoLogic's published rules (Karp et al. 2011, doi:10.4056/sigs.1794338). Those rules are permissive, so every call carries a confidence value built from its evidence:

    • each reaction is weighted by its strongest evidence: a DIAMOND hit scores 0.5 at 35% identity rising to 1.0 at 80%; EC-only and KO-only evidence score 0.45; an EC mapped straight to a MetaCyc reaction without a Rhea link scores 0.30
    • confidence is the mean weight over the pathway's reactions (0-1)
    • tier high means confidence >= 0.7, at least half of the present reactions backed by a sequence hit, every key reaction sequence-backed, and the MAG not outside the pathway's MetaCyc taxonomic range; medium means confidence >= 0.35; everything else is low

    How reliable the tiers are. The high-tier cut-offs (confidence 0.7 and the taxonomic-range condition) were fitted against EcoCyc, the hand-curated E. coli K-12 database, with E. coli MG1655 run through mag_analysis; the weights are the original estimates. For base (non-super) pathways that exist in MetaCyc:

    Tier Share of calls that are curated EcoCyc pathways Share of curated pathways called in this tier
    high 0.79 0.54-0.68
    medium 0.29-0.38 0.18-0.29
    low 0.04-0.07 0.02-0.03

    Ranges span runs with the full reference and with every Escherichia, Enterobacteriaceae or Enterobacterales protein removed from it, which is closer to a MAG from a novel genus. With 20-60% of the genes removed (an incomplete MAG) the high tier stayed at 0.75-0.79 precision and its recall fell to 0.18-0.53. Super-pathways are less reliable (high tier ~0.64), because they are called whenever all their components are. Treat low-tier calls as possibilities rather than findings. tools/metacyc_benchmark.py reruns the comparison for any curated PGDB you have (export, compare, degrade); see its --help. The step needs Bakta annotation (--annotator bakta). It is skipped, with one log line, when --metacyc_db is not given.

    Getting MetaCyc. MetaCyc is licensed by SRI International and is never downloaded automatically. You need one of:

    You have Where it comes from
    MetaCyc flat files (a tarball or directory containing pathways.dat, reactions.dat, classes.dat) a BioCyc subscription (flat-file download for MetaCyc)
    the Pathway Tools Linux installer (pathway-tools-XX.X-linux-64-tier1-install) a Pathway Tools licence from SRI (free for academic use)
    an existing Pathway Tools Apptainer image (.sif), e.g. from MetaPathways build_pt your site

    Setup (once per site):

    ./download-databases.sh --db_dir /path/to/databases --metacyc-refs          # open references
./download-databases.sh --db_dir /path/to/databases --metacyc <tarball|dir|installer|.sif>
# installer on an Apptainer-only host (e.g. an HPC cluster): give the MetaPathways image as the runtime
apptainer pull mp.sif docker://quay.io/hallamlab/metapathways:4.0.3
./download-databases.sh --db_dir /path/to/databases --metacyc pathway-tools-30.0-linux-64-tier1-install \
    --metacyc-runtime mp.sif
    Step Writes Time Disk
    --metacyc-refs <db_dir>/metacyc_refs/: Rhea, KEGG ko->reaction, GTDB r226->NCBI taxids, and the DIAMOND reference (Swiss-Prot plus one Rhea-annotated protein per UniRef90 cluster, 9.4M sequences) ~1 h, mostly downloads (UniProt idmapping 7 GB; TrEMBL ~40 GB is streamed through a filter, never stored) ~15 GB scratch at peak, 5.5 GB kept
    --metacyc (flat files) <db_dir>/metacyc/ seconds ~140 MB
    --metacyc (installer or .sif) <db_dir>/metacyc/, exported in batch mode from a temporary Pathway Tools install ~3 min 3.5 GB temporary

    The installer runs as your own user, with no root, inside the Pathway Tools runtime that ships in the MetaPathways image, and the install is deleted afterwards. <db_dir>/metacyc/ is created owner-only and carries a VERSION.json (MetaCyc release, source, date).

    Licence. Keep <db_dir>/metacyc/ private. Don't put it in container images, git repositories or shared or public locations. The pipeline outputs carry MetaCyc pathway and reaction identifiers and names, so share them under the same terms as MetaCyc itself.

    --db_dir finds <db_dir>/metacyc and <db_dir>/metacyc_refs automatically. Taxonomic-range rules use GTDB-Tk's classification (--run_gtdbtk). Without GTDB-Tk they use SendSketch contig calls (--run_sendsketch), which are less reliable, and the log says so; with neither, the range rules are off. Without them the high tier is less precise (0.73 instead of 0.79 on the EcoCyc benchmark). --metacyc_taxonomy sendsketch forces the SendSketch calls; none turns the range rules off.

    Outputs in metabolism/metacyc/:

    • metacyc_pathways.tsv: one row per bin (plus _community) and pathway with any evidence: the call and the rule that decided it, confidence and confidence_tier, reaction counts by evidence (n_seq, n_ec_only, n_ko_only, n_ec_direct_only), sequence identity, key and unique reaction support, up to 12 supporting hits (reaction=protein:UniProt:identity), and a MinPath-style parsimony flag (minpath)
    • metacyc_reactions.tsv.gz: one row per protein and MetaCyc reaction, with its evidence classes, DIAMOND identity, coverage and hit, and the ECs and KOs behind it
    • metacyc_bin_taxonomy.tsv: each bin's GTDB lineage and the NCBI taxids used for the taxonomic ranges
    • metacyc_hits.tsv.gz: the DIAMOND hits

    On 72,231 proteins (7 MAGs), the DIAMOND search took 21 min on 8 threads with a 17 GB peak (sensitive, -b 2), and the scorer took 14 s and 0.6 GB. For a co-assembly of ~13M proteins, expect the search to take ~1.5-2.5 h on a 192-CPU node (--metacyc_cpus 192; raise --metacyc_block_size to 4-6 and --metacyc_memory to ~96 GB for fewer passes over the reference). The scorer then takes ~20 min, ~5 GB, and as much scratch in its work dir as the input tables. Results do not depend on --metacyc_chunk; a smaller value only lowers memory.

    Dereplication¶

    --run_derep clusters the consensus bins (DAS Tool, plus Binette and MAGScoT when they run) at species-level ANI with galah, and keeps one representative per cluster: the genome with the highest completeness − 5 × contamination, less small penalties for contig count and ambiguous bases (galah's Parks2020_reduced). It needs --checkm2_db, and clusters only bins that CheckM2 scored. Within one run, it picks the best of the refiners' versions of each genome; it does not dereplicate across runs or co-assemblies.

    binning/derep/derep_clusters.tsv lists every consensus bin. Its status is representative, member (with its skani ANI and aligned fractions against the representative; NA if the pair falls below skani's 80% ANI screen), failed_quality (outside the completeness/contamination thresholds), or no_checkm2 (no CheckM2 estimate, e.g. a bin above --checkm2_max_bin_bp).

    Note: the bin-size cut-offs --binette_min_bin_bp, --binette_max_bin_bp, --checkm2_max_bin_bp and --gtdbtk_max_bin_bp are compared against the bin FASTA's size in bytes, which approximates its length in bp (headers and line breaks included). --derep_min_size_bp counts sequence bases.

    Parameter Default Description
    --run_derep false Dereplicate the consensus bins with galah (needs --checkm2_db)
    --derep_ani 95 ANI (%) at which genomes are clustered
    --derep_min_af 15 Minimum aligned fraction (%) for two genomes to cluster
    --derep_min_completeness 50 CheckM2 completeness (%) below which a bin is not clustered
    --derep_max_contamination 10 CheckM2 contamination (%) above which a bin is not clustered
    --derep_min_size_bp 500000 Bins shorter than this (bp) are not clustered, so a fragment cannot become a representative

    Databases¶

    Download all databases with the interactive menu:

    ./download-databases.sh --all --dir /path/to/databases

    Or download individually:

    ./download-databases.sh --checkm2   # CheckM2 (~3 GB)
./download-databases.sh --genomad   # geNomad (~3 GB)
./download-databases.sh --checkv    # CheckV (~2 GB)
./download-databases.sh --kaiju     # Kaiju nr_euk (~60 GB)
./download-databases.sh --gtdbtk    # GTDB-Tk (~85 GB)
./download-databases.sh --pgap      # NCBI PGAP HMMs incl. TIGRFAM (~2.7 GB)
./download-databases.sh --metacyc-refs        # MetaCyc open references (~5.5 GB)
./download-databases.sh --metacyc <source>    # licensed MetaCyc you supply (see MetaCyc pathways)

    Use --db_dir to auto-resolve paths from a standard layout:

    ./run-mag-analysis.sh --db_dir /path/to/databases ...

    Design Notes¶

    • Seven-binner consensus. SemiBin2, MetaBAT2, MaxBin2, LorBin, COMEBin, VAMB, VAMB-tax feed into DAS Tool + Binette + MAGScoT for consensus refinement.
    • Modular activation. MetaBAT2, DAS Tool, Bakta annotation (--annotator bakta) and ECOSSDB (--run_ecossdb, when metabolism runs) are on by default; every other module is off until enabled with its --run_* flag, or with the launcher's --all.
    • Technology-agnostic. Accepts assemblies from Nanopore, Illumina, HiFi, or any external assembler. Only requires FASTA + MetaBAT2-format depth table.
    • Persistent caching. Use --store_dir to skip completed processes across runs, even after work/ cleanup.
    • Quality tiers. The viz preprocessing tiers MAGs from CheckM2 completeness/contamination as HQ (>=90%, <5%), MQ (>=50%, <10%) or LQ; the MIMAG rRNA/tRNA criteria are not applied.
